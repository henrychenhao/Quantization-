A股量化交易系统设计方案

基于 Python 的本地半自动量化闭环 · 信号 → 人工下单 → 记账
方案版本 V1.0 · 2026 年 10 月

一、项目定位与核心理念

本系统面向个人投资者，是一套运行在本机（Mac/PC）的 A 股量化辅助系统：它不替你下单，只做三件事——按策略发现机会、把信号推到手机、成交后完成记账闭环。所有行情与账本数据留在本地，不做任何云端托管。这一定位直接来源于参考系统的实盘形态：它同样运行在一台 MacBook 上，通过微信推送信号，由人在券商 App 完成交易，再回系统确认记账。

半自动，不做全自动

系统只负责"发现"，买卖决策与下单由人完成。规避程序化接入券商的合规门槛与账户风险，也保留人对极端行情的最后否决权。参考系统的每条信号都注明"请自行决策下单，成交后在系统确认记账"。

本地私有运行

单机部署，Web 控制台走 127.0.0.1 访问，行情库、账本、日志全部落本地磁盘。每日心跳推送（自选数、现金、持仓市值、总资产）既是账户播报，也是进程存活探针。

小步可验证

每一期交付都能独立跑出结果：先有回测，再有信号，后有界面。任意阶段停下，系统都处于可用状态；加一个策略不动引擎一行代码（插件注册制）。

三、总体架构

五层结构，依赖单向向下：上层只调用相邻下层，策略层以插件注册表组织，引擎层不感知具体策略实现。任何一层可独立替换（例如数据源适配层更换行情供应商，不影响策略与引擎）。

应用层

Web 控制台（FastAPI + Jinja2 + ECharts，本机 8000 端口）· 心跳与信号推送（企微机器人 / Server酱）· 分模块结构化日志。

引擎层

实时监控引擎（尾盘触发 + 四道校验 + 去重）· 回测引擎（逐 K 线事件驱动 + 绩效计算）· 策略推荐评分（P4）。

策略层

策略插件注册表（六大经典策略）· 指标库（MA / MACD / BOLL / RSI / Donchian）· 统一信号协议（方向/数量/理由）。

数据层

行情适配器（AkShare 主源 + BaoStock 备源）· K 线库（Parquet 按代码分区）· 业务库（SQLite 六张表：自选/信号/流水/持仓/快照/推送日志）。

接入层

APScheduler 调度（心跳、尾盘信号、收盘数据同步三类 cron 任务）· config.yaml 单一配置源 · 交易日历本地缓存。

运行载体

个人电脑常驻进程（macOS launchd 托管），单命令启动；全部组件零外网依赖，仅行情拉取与推送出网。

三条主链路

  • 信号链路（交易日 14:50）：拉实时快照 → 逐标的 × 逐绑定策略计算指标 → 四道校验闸门 → 生成信号入库 → 推送企微 → 人工下单 → 回执记账 → 更新持仓与现金。
  • 心跳链路（交易日 09:35）：读取账户快照 → 推送"监控 N 只自选（开启 M 只）· 现金 · 持仓市值 · 总资产"。
  • 数据链路（每个交易日 17:30）：增量拉取当日日线 → 追加 Parquet → 刷新交易日历缓存。

四、技术选型

选型原则：只选主流、文档齐全、无编译负担的组件，让精力花在策略与引擎上，而不是环境维护上。全部组件 pip 即装。

五、核心模块设计

5.1 行情数据模块

适配器模式隔离数据源：DataSource 接口定义 get_daily（日线批量）与 get_spot（实时快照）两个方法，AkShare 与 BaoStock 各实现一份，主备可切换，切换不动上层代码。首次使用全量拉成历史，此后每日增量追加；交易日历本地缓存，调度器先判交易日后才触发任务。

  • 统一 K 线 schema：code / date / open / high / low / close / volume / amount，个股与 ETF 完全同构。
  • 标的元数据打标交易规则：股票与多数场内 ETF 为 T+1，跨境 ETF（如 513530 港股通红利、恒生科技类）为 T+0；回测撮合与信号校验都读取该标记。
  • ETF 场内交易免印花税、股票卖出收印花税，费率模型按品种区分。

5.2 策略插件层

所有策略实现统一接口，由注册表装配；自选股绑定策略时引用注册表中的策略标识。新增策略 = 新增一个文件 + 注册表加一行。

5.3 回测引擎

事件驱动逐 K 线回放：窗口起点前的历史 K 线仅用于指标预热，仿真从窗口起点开始、初始空仓——与参考系统口径一致，杜绝前视偏差。多策略对比时，六个策略跑同一区间、同一初始资金，结果可直接横向比较。

  • 绩效八指标：总收益、年化收益、超额收益（对买入持有基准）、最大回撤、夏普比率、回合胜率（一买一卖计一回合）、交易笔数、期末资产。
  • 规则差异处理：T+0 标的当日可卖、T+1 强制隔日；买入按 100 股整手；ETF 免印花税。

5.4 实时监控引擎：四道校验闸门

每条信号在推送给用户之前必须过完四道闸门，任何一道不过即跳过并写日志——参考系统的引擎日志（"买入信号但资金不足/价格异常，跳过"）证明这正是其实盘行为。

信号前置校验规则
闸门规则不通过的处置
价格校验快照价非空非零、非涨跌停一字板可成交、非停牌跳过并记日志（qsig.engine 前缀）
资金校验买入信号需"可用现金 ≥ 建议股数 × 现价"，建议股数自动向下取整手按可用资金收缩股数，或不足一手则跳过
持仓校验卖出信号需当前持仓 ≥ 建议卖出股数按实际持仓收缩，持仓为零则跳过
去重校验同一标的 × 同一策略当日只生成一条信号丢弃重复，日志留痕

信号状态机只有三个态：待处理（pending）→ 已跟随（followed）或已忽略（ignored）。点击"已跟随"必须补录成交流水，系统随即更新持仓与现金——这保证后续资金校验用的永远是真实账本，也让胜率统计天然是"已跟随口径"而非纸面口径。

5.5 记账模块

记账以交易流水为唯一事实源：持仓（股数、均价）与现金全部由流水表推导，另设手工调仓流水（分红、拆合、误记修正）兜底。每个交易日收盘后生成资产快照（现金、持仓市值、总资产），供心跳推送与收益曲线使用。回执记账支持两种入口：Web 表单填写，或回复推送消息中的流水号带数量价格。

5.6 推送模块

通道抽象 + 消息模板。企微群机器人为默认主通道（免费、稳定、支持 markdown 卡片）；Server酱通道直推个人微信，配置里切换。推送失败自动重试两次并落推送日志表，日志里可查每条信号的触达状态。

八、实施路线图

四期主体 + 一期进阶，每期结束都是可独立使用的系统。先回测后实盘信号，先命令行后界面，先把钱算清楚再谈自动化。

  1. P0 · 第 1-2 周 · 地基与回测闭环

    搭环境与工程骨架，数据层（AkShare 适配 + Parquet + 交易日历）、指标库、双均线策略、回测核心与绩效八指标；产出：任选一个 ETF 命令行跑出单策略回测报告。这是全系统价值密度最高的一步，验证"数据 → 策略 → 回测"最小闭环。

  2. P1 · 第 3-4 周 · 策略矩阵与多窗口

    补齐六个策略与注册表，实现多策略横向对比与七档多窗口评估（对买入持有基准），K 线信号图、净值/回撤对比图、月度热力图三类可视化。

  3. P2 · 第 5-6 周 · 信号、推送与记账闭环

    实时监控引擎 + 四道校验闸门 + 信号表，企微推送（心跳与信号模板），回执记账与持仓推导。此期结束后即可低资金实测信号链路，暂用命令行交互，不等界面。

  4. P3 · 第 7-8 周 · Web 控制台

    自选监控、回测工作台、信号中心、账户账本四页上线，ECharts 图表与配置表单化，本机 127.0.0.1:8000 常驻。

  5. P4 · 进阶（按需启动）

    策略推荐评分（近期收益/最深回撤，对齐参考系统）与一键应用、盘中分钟级轮询、组合级风控（单标的仓位上限、总回撤熔断）、多市场数据源扩展预留。

十、待确认决策点

以下三点不影响架构，但影响 P0 的落地形态，开工前需定：

部署形态

Mac 本机常驻（与参考系统一致，零成本，合盖风险由尾盘单时点规避）或轻量云服务器（7×24 稳定，推送不断线）。建议先本机，信号链路跑稳后再迁。
